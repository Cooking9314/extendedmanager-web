Документация / Конфигурация

Обзор и быстрый старт

Extended Manager, ядро управления сервером: один JAR закрывает вход и регистрацию, наказания, чат, миры, NPC, Discord, перезапуск и HTTP API. Всё настраивается YAML-файлами в папке плагина.

Что внутри

Семь модулей, каждый со своей папкой настроек. По умолчанию все выключены: свежая установка создаёт только файлы ядра.

  • security
  • chat
  • motd
  • npc
  • discord
  • api
  • utils

Установка

  1. Положите JAR плагина в папку plugins/ сервера.
  2. Перезапустите сервер: плагин создаст файлы конфигурации.
  3. Включите нужные модули в config.yml → modules.
  4. Сохраните файл и выполните /em reload: папки и команды модуля появятся без перезапуска.

Готовые JAR и доступ к репозиторию распространяются по приглашению автора: сайт описывает плагин, но не раздаёт сборки.

Справка по всем командам: /em help, состояние сборки и модулей: /em info.

Требования

СерверBukkit, Spigot, Paper или Purpur 26.3; для 26.2 есть отдельная сборка того же 0.14.1
Java25 или новее на сервере
ПроксиBungeeCord, Waterfall или Velocity с адаптером ExtendedManager
БазаSQLite без настройки; MySQL, MariaDB или PostgreSQL: для сети серверов
 
modules:
  security: true
  chat: true
  motd: true
  npc: false
  discord: false
  api: false
  utils: false

Ядро и модули

Файл config.yml главный: модули, префикс, интеграции, рассылка, AFK, привилегии, геолокация, прокси, сеть, API и база данных.

Модули

Ключ modules решает, какие папки и файлы создаются и какие команды работают. Выключенный модуль отвечает сообщением module-disabled, его файлы не читаются и не удаляются.

modules:
  security: false
  chat: false
  motd: false
  npc: false
  discord: false
  api: false
  utils: false

Основные секции

prefixПрефикс сообщений ядра в MiniMessage; пустая строка отключает префикс
hooksИнтеграции: PlaceholderAPI, LuckPerms, Voice Chat, SkinsRestorer, TAB, WorldGuard
broadcastСвой формат серверной рассылки /say и имя автора для консоли
afkПростой игроков: секунды, сообщения, значок для TAB и «бонусы»
ranks/setrank и /givedonate: режим LuckPerms и оформление покупки
updateПроверка обновлений: GitHub или свой URL, интервал и уведомление операторов
geo/geolocate: сервис, язык, кэш и таймаут запроса

/em reload перечитывает конфиги и применяет набор модулей сразу. Служебный config-version обновляется сам: новые ключи добавляются, ваши значения сохраняются.

База данных

Секция database файла config.yml. По умолчанию SQLite: файл в папке плагина, ничего настраивать не нужно.

Типы баз

sqliteФайл data.db в папке плагина; драйвер поставляет Paper
mysqlВнешний сервер: host, port, database, username, password, use-ssl
mariadbРаботает по протоколу MySQL; без своей секции берёт значения mysql.*
postgresqlДрайвер внутри JAR плагина; имена таблиц сворачиваются в нижний регистр

Пример: MySQL для сети

database:
  type: mysql
  table-prefix: em_
  mysql:
    host: 127.0.0.1
    port: 3306
    database: extendedmanager
    username: root
    password: ""
    use-ssl: false

База и пользователь должны существовать заранее: плагин создаёт только свои таблицы с префиксом em_. Общая база нужна для кросс-серверных сессий (network.shared-database).

Перед импортом дампа плагин создаёт резервную копию текущей базы в папке database/; при ошибке импорт останавливается.

Документация / Интеграции

Прокси и сеть

Секции proxy и network: кто стоит перед сервером и как серверы рассказывают друг другу, кто авторизован.

Тип прокси

none: одиночный сервер; bungeecord: BungeeCord и Waterfall; velocity: Velocity, которому нужен адаптер ExtendedManager из папки velocity сборки.

proxy:
  type: velocity
  channel: ""
  check-server-config: true

Присутствие и сессии

server-idУникальный id сервера в сети; пусто берёт имя из server.properties
heartbeat-secondsКак часто рассылается присутствие игроков (0 выключает)
forwardingРассылать присутствие через канал прокси
shared-databaseПродлевать сессии в общей базе auth_sessions

При bungeecord и velocity плагин сверяет spigot.yml: без включённой поддержки прокси сервер видит адрес машины-прокси вместо адресов игроков, и вход по IP ошибается.

Документация / Модули

Безопасность

Модуль security: регистрация и вход, таймер, сессии, капча и лимбо. Файл: security/security_config.yml.

Вход и пароли

Пока игрок не вошёл, он не двигается, не пишет в чат и не использует команды. Пароли хранятся только как Argon2id-хеши.

auth:
  enabled: true
  enable-min-length: true
  min-length: 6
  enable-max-length: true
  max-length: 32
  max-attempts: 3

Лимбо, капча и таймер входа работают только при включённом модуле security.

Лимбо и капча

Неавторизованный игрок ждёт в тёмном пустом мире em_limbo, а после /register вводит код с карты, как в LimboAuth. После входа возвращается в свой мир и режим игры.

captcha:
  enabled: true
  mode: map
  length: 5
  attempts: 3
  expire-seconds: 120
limbo:
  enabled: true
  world: em_limbo

Сессии и таймер

sessions.duration-minutesСколько минут вход с того же IP идёт без /login (0 выключает)
sessions.cross-serverСессия открывает вход на все серверы сети через канал прокси или общую базу
timer.secondsСекунд на регистрацию или вход, дальше кик (0 отключает таймер)
timer.typeГде показывать отсчёт: bossbar или actionbar

Старые хеши PBKDF2 продолжают работать: при удачном входе пароль молча перезаписывается на Argon2id, сброса паролей не происходит.

Документация / Сообщения

Чат и рассылка

Модуль chat: форматы чатов, анти-спам, рассылка по расписанию и админ-чат. Файлы: chat/chat_config.yml, chat/broadcast.yml, chat/adminchat_config.yml.

Форматы

Локальный и глобальный чат со своими форматами и радиусом; разметка MiniMessage и старые коды &.

enabled: true
allow-player-formatting: auto
format: "<gray>%em_displayname%</gray> <dark_gray>»</dark_gray> <white>%em_message%</white>"

Рассылка управляется командой /broadcasts, её виды лежат в chat/broadcast.yml.

Анти-спам

Секции anti-spam, anti-caps и links: пауза между сообщениями, доля капса и поведение ссылок в чате настраиваются отдельно.

Рассылка

Общие ключи рассылки и список видов; у каждого вида свои header, footer, sound, volume и pitch: вид без них выходит без рамок и звука.

enabled: true
interval: 300
order: sequence
jitter: 0
min-players: 1
console: true

Админ-чат

Сообщение с префиксом @ уходит держателям права просмотра админ-чата. Консоль тоже пишет туда: /say @текст: автором строки становится broadcast.console-name.

MOTD и иконка

Модуль motd: своё описание в списке серверов и иконка. Файл: motd/motd_config.yml.

Две строки в MiniMessage с плейсхолдерами онлайна, TPS и версии.

lines:

Иконка

PNG 64×64; путь указывается относительно папки motd. Иконка работает и при enabled: false: её можно показывать без своего текста.

icon:

На прокси Velocity своё описание и иконку отдаёт адаптер: секция motd его config.yml повторяет эти ключи, а плейсхолдеры там: {online}, {max}, {servers}.

NPC

Модуль npc: жители с именем, скином, позой и диалогами. Файлы: npc/npc_config.yml и файлы отдельных NPC.

Создание

/npc create <id> <имя> вписывает NPC в реестр npcs; запись без файла создаёт файл-образец после /npc reload. По умолчанию реестр пуст.

Внешность и поведение

defaults.skinНик игрока для скина, если у NPC не задан свой
defaults.entityТело моба игры (VILLAGER, HORSE, CAT…); пусто даёт манекен на Paper
defaults.glowПодсветка световым контуром
defaults.look-at-playerСледить ли за ближайшими игроками
defaults.hologram-enabledГолограмма над NPC
defaults.cooldownПауза между кликами одного игрока, секунды
defaults.permissionПраво на взаимодействие; пусто разрешает всем

Команды NPC доступны при включённом модуле npc.

Скины

Скин грузится асинхронно: сначала через SkinsRestorer, иначе напрямую с серверов Mojang. Секция skin-cache задаёт таймаут запроса, паузу повтора и число попыток.

Discord-бот

Модуль discord: статус сервера, события игроков в канал, привязка аккаунтов и слеш-команды. Файл: discord/discord_config.yml.

Запуск

enabled: true
token: ""
guild-id: ""

Токен создаётся в портале разработчиков Discord, guild-id задаёт id вашего сервера Discord. Без них модуль не подключается.

Привязка и защита

Секция link описывает привязку игрового аккаунта к Discord, two-factor: подтверждение входа; аккаунты с подтверждением не пропускаются кросс-серверными сессиями. Секции activity и admin задают статус бота и тех, кто вправе им управлять.

Токен бота является секретом: не публикуйте файл конфигурации с заполненным token и не передавайте его третьим лицам.

Документация / Модули

HTTP API

Модуль api поднимает HTTP API для приложения управления: игроки, аккаунты, скины, инвентарь, чтение базы, консоль и SSE-потоки событий.

Запуск

Требуется Paper или Purpur. Адрес и порт живут в секции api файла config.yml, включается модуль ключом modules.api.

api:
  host: "127.0.0.1"
  port: 25590

Ключ доступа

Ключ генерируется один раз при первом запуске модуля: 48 символов, 288 бит энтропии. Ключ хранится в таблице <префикс>meta, поэтому переживает рестарты и перенос конфига. Показать его может только /em app key; в файлы и журнал ключ не попадает. Запросы сверяются по SHA3-512.

HTTP не шифруется: подключайтесь через localhost, VPN или SSH-туннель. Маршруты /api/v1/* требуют заголовок Authorization: Bearer <ключ>.

Маршруты

/healthСостояние сервера и отсчёта перезапуска
/api/v1/server/restartЗапуск и отмена отсчёта перезапуска телом {"action":"schedule","minutes":5}
игрокиСписок, скины, действия и инвентарь
аккаунтыПривязки адресов, история наказаний
база и консольЧтение таблиц и команды консоли, поток журнала через SSE

Документация / Модули

Перезапуск сервера

Модуль utils: остановка по расписанию, командой и из приложения: с предупреждениями, киками и сохранением миров. Файл: utils/restart_config.yml.

Расписание

Интервал в минутах и конкретные моменты вида 04:30. Моменты, прошедшие до включения модуля, не догоняются пачкой.

schedule:
  interval-minutes: 0
  times:
    - "04:30"

Предупреждения

warning.before-seconds: пороги отсчёта (часы, минуты и последние секунды), warning.actionbar-seconds: сколько секунд остаток держится над хотбаром. Предупреждение уходит и в чат, и в консоль.

Остановка

before.console-commandsКоманды консоли перед остановкой
before.kick-playersКикнуть игроков с причиной из messages
before.save-worldsСохранить игроков и каждый мир по отдельности
stop.methodshutdown: штатная остановка, stop: команда stop, exit: закрыть JVM
stop.grace-secondsСтраховочный таймер, если штатная остановка не началась

Статус отсчёта показывает /em restart status, отмена запланированного перезапуска: /em restart cancel.

Запуск отсчёта

Три способа: планировщик по расписанию, команда /em restart <минуты|cancel|status> и API POST /api/v1/server/restart. Снятый вручную отсчёт повторно не всплывает.

Документация / Команды

Общее о командах

У плагина 56 команд. Здесь то, что работает у всех одинаково: цели и селекторы, имена прав, блоки в command_config.yml и что бывает с командами выключенных модулей.

Цели и селекторы

Команда принимает ник игрока или селектор: @a все, @p ближайший, @r случайный, @s сам отправитель. Селектор требует право extendedmanager.command.selector, а действие над другим игроком требует extendedmanager.command.<команда>.others. Если селектор не выбрал ни одной цели, отвечает selector-empty из main_messages.yml.

Права

Право команды называется extendedmanager.command.<имя>, его описание и значение по умолчанию заданы в plugin.yml. Полный доступ даёт extendedmanager.*: он включает и права команд, и служебные права вроде extendedmanager.command.selector или extendedmanager.command.kickall.exempt. У /afk, /gamemode и части служебных прав значение по умолчанию true, то есть команда доступна всем игрокам.

Блок команды в command_config.yml

С 0.14.1 у каждой команды свой блок из enable, aliases и cooldown с duration и bypass. Алиасы работают и в чате: /gm выполняется как /gamemode с её правом и задержкой, а задержка отвечает сообщением command-cooldown. Как устроен блок, в каком порядке применяется и что сохраняется в backups/, описано в разделе «Настройки команд»; правки применяет /em reload.

Выключенные и удалённые команды

Команда, выключенная в command_config.yml, не выполняется, а в /em help её не видно. Команды модулей зависят ещё и от modules: /register и /login работают при modules.security. Имя команды прописано в plugin.yml, поэтому новое имя появляется только после перезапуска сервера.

Команды /nickname и /forcename удалены вместе с модулем ников: видимое имя даёт аккаунт, %em_displayname% отдаёт имя аккаунта. Ключи commands.nickname и commands.forcename автообновление убирает из command_config.yml.

Включение и отключение

В command_config.yml секция commands включает и выключает команды. Отсутствующая в списке команда всегда включена; false отвечает сообщением command-disabled и исчезает из автодополнения.

commands:
  afk:
    enable: true
    aliases:
      - "away"
    cooldown:
      enable: false
      duration: 0
      bypass:
        name: "extendedmanager.command.afk.cooldown.bypass"
        type: "permission"
  fly:
    enable: true
    aliases: []
    cooldown:
      enable: true
      duration: 60
      bypass:
        name: "extendedmanager.command.fly.cooldown.bypass"
        type: "OP"

С 0.14.1 у команды не одно значение, а блок. enable включает её, aliases задаёт дополнительные имена ("away" вызывает /afk; пустой список [] их не добавляет, а имена из plugin.yml работают всегда), cooldown держит задержку: duration в секундах и bypass, который её снимает. У bypass два поля: name это узел права, а type принимает permission (хватает права) или OP (только операторам сервера). Ответ о задержке берётся из command-cooldown в main_messages.yml, где %em_seconds% показывает остаток. Плоский вид (fly: true) читается по-прежнему, а автообновление переводит команды на блоки и сохраняет прежнюю копию файла в backups/.

Свои алиасы применяет плагин, поэтому достаточно /em reload: игрок пишет /away, выполняется /afk с её правом и задержкой. Алиас не перекрывает уже зарегистрированную команду и не действует, если одно имя дали двум командам.

Правка применяется после /em reload. Команды модулей зависят ещё и от modules: register и login работают при modules.security. Новое имя команды регистрируется в plugin.yml и появляется только после перезапуска сервера.

Блок команды

Алиасы и задержка в command_config.yml действуют на команду целиком, у подкоманд отдельных блоков нет.

command_config.ymlcommands.emкак устроен блок

  em:
    enable: true
    aliases: []
    cooldown:
      enable: false
      duration: 0
      bypass:
        name: "extendedmanager.command.em.cooldown.bypass"
        type: "permission"
enable
Включает команду. false отвечает сообщением command-disabled: выключенная команда не выполняется, её не видно в /em help и в автодополнении Tab.
aliases
Дополнительные имена: список вроде ["away"] вызывает /em и по слову /away. Имена из plugin.yml работают всегда, а свои алиасы применяет сам плагин, поэтому хватает /em reload.
cooldown.enable
Включает задержку между запусками /em одним игроком.
cooldown.duration
Сколько секунд ждать после запуска: 0 не ждать.
cooldown.bypass
Кто задержку пропускает. name это узел права, type: permission даёт проход по выданному праву, type: OP работает только у операторов сервера.

Голова компонентом

В формат сообщения попадает тег <em_playerhead:имя>, а ядро превращает его в компонент головы. Скин онлайн-игрока берётся из профиля Paper, для игрока не в сети используется кэш, а если текстур в кэше нет, остаются имя или UUID и клиент дорисует скин сам. Где компонент недоступен: PlaceholderAPI, TAB, HTTP API и ядра без Adventure 5 получают прежнюю ссылку, поэтому форматы чата прежних версий продолжают работать.

Голова остаётся ссылкой там, где текст не проходит через чат плагина: в голограммах NPC и в рассылках сторонних плагинов.

Плейсхолдеры

Без аргумента берётся игрок, к которому обращён плейсхолдер; после двоеточия можно написать имя или uuid: %em_playerhead:Notch%, %em_playerhead:59c987a2-4ef3-48e5-a291-00abe9ca8f12%. Ссылка собирается как база/<имя или uuid>/<размер>.png, поэтому %em_playerhead% отдаёт https://mc-heads.net/avatar/59c987a2-4ef3-48e5-a291-00abe9ca8f12/8.png, а %em_playerbody% ведёт к https://mc-heads.net/player/59c987a2-4ef3-48e5-a291-00abe9ca8f12/16.png. Работают плейсхолдеры там же, где и остальные %em_*%: форматы чата и админ-чата, рассылки, предупреждения о перезапуске, голограммы NPC, TAB и PlaceholderAPI. Полный список ключей в разделе «Плейсхолдеры».

В путь попадает только имя игрока или uuid: адреса вне букв, цифр, «_» и «-» и длиннее 40 символов плагин не собирает, вместо ссылки выходит пустая строка. Пустой avatar_api_url или body_api_url выключает внешний сервис.

format: "<gray>%em_playerhead% %em_displayname%</gray> <dark_gray>»</dark_gray> <white>%em_message%</white>"

Плейсхолдеры

Плейсхолдеры %em_*% подставляют в тексты имя игрока, SID аккаунта, состояние наказания, группу LuckPerms, онлайн сервера и голову скина. Часть значений знает реестр плагина, остальные передаёт сама команда или модуль.

Два вида

Реестр39 ключей, которые плагин разбирает сам: %em_sid%, %em_group%, %em_tps%, %em_playerhead%. Они работают и внутри плагина, и через PlaceholderAPI, поэтому их видят TAB и сторонние плагины.
МестныеЗначения одного сообщения: %em_reason%, %em_duration%, %em_page%. Их подставляет команда, которая отправляет текст, через PlaceholderAPI они не отдаются.

PlaceholderAPI не обязателен: у реестра есть собственный резолвер, поэтому %em_playerhead% и другие ключи подставляются в чат, рассылки и TAB даже на сервере без PlaceholderAPI. Статус интеграции показывает /em hooks.

Аргумент после двоеточия

Ключи головы и скина принимают имя или UUID: %em_playerhead:Notch%, %em_playerbody:59c987a2-8b1a-4d5f-9c2c-1f3a7d2e4b55%. Без аргумента берётся UUID того игрока, кому принадлежит строка. Аргумент сохраняют в том регистре, в котором написали, имена игроков регистр различают.

  body_size: 16

Имя из аргумента плагин не ищет в базе: плейсхолдеры подставляются в строки чата, а запрос к базе в основном потоке остановил бы сервер. Имя и UUID разбирает внешний сервис картинок.

Правила подстановки

  • Неизвестный ключ остаётся в тексте как написан, поэтому опечатку видно в чате, а не пустое место.
  • Регистр имени ключа не важен: %EM_SID% и %em_sid% одинаковы. Аргумент после двоеточия сохраняет регистр.
  • Ключи игрока без игрока отдают пустую строку, а состояния banned, muted, afk, vanished и прочие отвечают off.
  • Значения наказаний, предупреждений и AFK берутся из кэша модулей, поэтому форматы чата и TAB не обращаются к базе на каждое сообщение.
  • %em_maintenance% удалён вместе с модулем техобслуживания, ключи античита убраны с 0.14.0: в текстах их быть не должно.
  • Правки форматов применяет /em reload, проверку связи с PlaceholderAPI показывает /em hooks.

Приложение управления

Extended Manager App для Windows подключается к HTTP API плагина и показывает сервер в реальном времени. Само приложение распространяется отдельно от плагина.

Подключение

  1. Включите модуль modules.api: true и выполните /em reload (нужен Paper или Purpur).
  2. Задайте адрес и порт в config.yml → api (по умолчанию 127.0.0.1:25590).
  3. Покажите ключ командой /em app key и скопируйте его.
  4. В приложении добавьте сервер: адрес, порт и ключ доступа.

HTTP не шифруется: подключайтесь через localhost, VPN или SSH-туннель. Ключ передаётся в заголовке Authorization: Bearer и сверяется по SHA3-512. Подробнее в разделе «HTTP API».

Возможности

  • живая консоль и события
  • игроки и скины
  • аккаунты
  • инвентарь
  • чтение базы
  • аналитика
  • перезапуск

Консоль и события идут через SSE-потоки, игроки и скины идут через маршруты /api/v1/*, чтение базы и инвентарь через соответствующие маршруты API.

Несколько серверов

Серверы сети за Velocity или BungeeCord добавляются в одно окно: у каждого свой адрес и ключ. Присутствие и кросс-серверные сессии настраиваются на стороне плагина, раздел «Прокси и сеть».

Вопросы и проблемы

Частые вопросы по установке, модулям, прокси, API и наказаниям.

Если ответа нет, начните с /em info и /em hooks: они показывают версию, модули и состояние интеграций.

Команда отвечает module-disabled

Модуль выключен. Включите его в config.yml → modules, сохраните файл и выполните /em reload: папки, файлы и команды модуля появятся без перезапуска.

Вход по IP ошибается за прокси

Без включённой поддержки прокси сервер видит адрес машины-прокси вместо адресов игроков. Включите поддержку прокси в spigot.yml (bungeecord: true для BungeeCord и Waterfall) и передачу адресов на Velocity (forwarding в velocity.toml). Плагин сверяет это при proxy.check-server-config: true.

Приложение не подключается к API

Проверьте: модуль api включён, сервер на Paper или Purpur, адрес и порт в config.yml → api совпадают с настройками приложения, порт не закрыт firewall. Ключ показывается командой /em app key. HTTP не шифруется: используйте localhost, VPN или SSH-туннель.

Нужна версия для 26.2

Для Minecraft 26.2 есть отдельная сборка того же 0.14.1 (дерево 26.2 в репозитории). Основная сборка рассчитана на Paper API 26.3.

Где новые ключи конфигурации

Служебный config-version обновляется сам: при первом запуске новой версии недостающие ключи добавляются, а ваши значения сохраняются. Настройки наказаний и SID переехали в punishments.yml и SID_config.yml автоматически.

В 0.14.1 автообновление делает три структурных шага: переводит секцию commands на блоки enable, aliases и cooldown, переименовывает ключи с api на app и убирает em api из help-groups. Ключи удалённых /nickname и /forcename исчезают из файлов. Перед каждым таким шагом файл копируется в backups/, поэтому прежнюю правку можно вернуть.

Бан по адресу задел других игроков

За одним адресом может стоять несколько человек. Оставьте ip-link.skip-local: true и переключите ip-link.action: warn: тогда администрация получает предупреждение, а автоматического бана нет.
